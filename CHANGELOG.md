## 0.0.0.3 — 16.10.2026

**Тесты для ERP.Управление холдингом выделены в собственное расширение.**
Первая публикация расширения `YAXUNIT_ERPUH`: юнит-тесты общего модуля `ОбщегоНазначения`
конфигурации ERP.Управление холдингом.

> Релиз: [`0.0.0.3`](https://github.com/madmar1o/yaxunit_erpuh/releases/tag/0.0.0.3) —
> собранное расширение `yaxunit_erpuh-0.0.0.3.cfe` (11 643 б,
> SHA256 `0B15E973E0D0C7E226FBBB6DF05DB47D9014ABF782B17B16EE8139C7D5BF07F2`).
> Ассет выгружен из базы, в которой стоит проект EDT (`infobaseSync: inSync`), и совпадает
> с исходниками тега побайтово.

### Добавлено

- `exts/yaxunit_erpuh/` — расширение `YAXUNIT_ERPUH`, полный проект исходников для EDT:
  - общий модуль `ОМ_ОбщегоНазначения` — 5 наборов, 31 тест, 51 проверка;
  - `docs/modules/ОбщегоНазначения.md` — TDD-спецификация: требование → шаги «дано / когда / тогда» → проверки;
  - `docs/knowledge/` — база знаний: разбор замечаний EDT на модули движка, чтение чисел прогона,
    метод проверки честности тестов, разбор потерянного комментария при переносе теста;
  - `README.md` — состав, требования, установка (исходниками и через `.cfe`), запуск тестов;
  - `GIT-FLOW.md` — правила веток, версий и публикации.
- `CHANGELOG.md` (этот файл) — журнал публикаций в `develop`.
- `.github/workflows/erpuh-publish-check.yml` — проверка публикации: запрещённые файлы и содержимое,
  целостность структуры расширения. Публикации помечаются `[skip ci]` (движковый CI форка наше
  расширение не проверяет), поэтому проверку можно запускать вручную: Actions → «Проверка публикации
  расширения YAXUNIT_ERPUH» → Run workflow.

### Изменено

- тесты больше не живут внутри движка: `exts/yaxunit` — чистый движок, обновляется из upstream
  без наших правок и конфликтов;
- тест вывода сообщения пользователю перенесён из отдельного модуля и влит в `ОМ_ОбщегоНазначения`
  (набор «сообщения пользователю»), имя метода приведено к конвенции «имя теста начинается
  с имени проверяемого метода»: `СообщитьПользователюВыводитСообщениеВОчередь`.
