# Правила работы с форком: ветки, версии, публикация

Форк `yaxunit_erpuh` — публичный репозиторий расширения с тестами для ERP.Управление холдингом.
Здесь лежат две линии: движок YAxUnit (обновляется из upstream) и наши тесты.
Правила ниже касаются прежде всего наших тестов.

## Ветки

| Ветка | Назначение | Что в ней бывает |
| --- | --- | --- |
| `develop` | публикация результатов | только слияния из `dev_madmar1o`; никаких прямых коммитов |
| `dev_madmar1o` | рабочая ветка | текущая разработка тестов, промежуточные коммиты |
| `feature/tests-<модуль>` | короткая ветка под модуль | один тестируемый модуль ERPUH |
| `docs/<тема>` | короткая ветка под документацию | правки `docs/` и README |

Поток:

```
feature/tests-<модуль> ──merge──► dev_madmar1o ──merge──► develop ──tag──► 0.0.0.n+1
                                         │
обе ветки пушатся в форк, но только develop получает теги и записи в CHANGELOG
```

- Прогон тестов и проверка честности выполняются **до** слияния в `develop`.
- В `develop` попадают только результаты: рабочая история остаётся в `dev_madmar1o`.
- Слияние в `develop` — обычный merge-коммит; fast-forward не используется, чтобы в истории
  публикации были видны обе точки.

## Версии и теги

- Тег — на `develop`, формат `0.0.0.n` (`0.0.0.1`, `0.0.0.2`, …), линия версий **непрерывна**.
- Версия ставится после того, как изменение проверено и слито в `develop`.
- Тег помечает состояние расширения, которое можно собирать в `.cfe` и ставить в базу.
- Движок версионируется отдельно (теги upstream); наш тег к его версии не привязан, но в
  `CHANGELOG.md` указывается, с какой версией движка тесты проверялись.

## Публикация

1. Собрать изменения в `feature/*` или `docs/*`, прогнать тесты.
2. Проверить честность: инверсия ожиданий → набор красный целиком → восстановление → зелёный
   (метод — `docs/knowledge/honesty-check.md`).
3. Слить в `dev_madmar1o`, запушить.
4. Добавить запись в `CHANGELOG.md`: что изменилось, чем проверено, результат прогона.
5. Слить `dev_madmar1o` в `develop` merge-коммитом и поставить тег `0.0.0.n+1`.
6. В сообщении коммита и тега указывать `[skip ci]`: CI движка в этом форке не предназначен
   для сборки нашего расширения, а наши проверки выполняются локально.

## Обновление движка

Обновления YAxUnit берутся из upstream:

```
git remote add upstream https://github.com/bia-technologies/yaxunit.git
git fetch upstream
git checkout develop && git merge upstream/develop
```

Расширение с тестами не заимствует объекты движка и не правит его файлы, поэтому слияния должны
проходить без конфликтов. Если конфликт всё-таки возник — править нужно движковую часть,
`exts/yaxunit_erpuh` трогать нельзя.

## Что не публикуется

- собранные `.cfe`, `.cf`, `.dt` и файлы информационных баз — только исходники;
- выгрузки и дампы конфигураций, вендорский код ERP.Управление холдингом;
- параметры подключения к базам, логины, пароли и прочие секреты;
- инструменты и документация внутреннего репозитория сопровождения.

Проверка на всё это — автоматическая: workflow
[`erpuh-publish-check.yml`](../../.github/workflows/erpuh-publish-check.yml) в корне репозитория.
