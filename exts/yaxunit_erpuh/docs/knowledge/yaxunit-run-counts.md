# Сколько тестов в прогоне: «51», «31» и «5» — что есть что

**Симптом.** Числа в разных местах не совпадают: в отчёте прогона «51 / 51 PASSED», в сводке отчёта
Allure «всего 31», а в спецификации — «5 наборов, 31 тест, 51 проверка». Возникает подозрение, что
часть тестов не выполнилась.

**Причина.** Это разные уровни одной и той же картины, а не расхождение:

| Число | Что считает |
| --- | --- |
| 5 | наборы (`ДобавитьТестовыйНабор`): описания типов, метаданные, преобразование данных, строки/хеш/язык, сообщения пользователю |
| 31 | тестовые методы: процедуры, объявленные в тестовом модуле |
| 51 | проверки: утверждения `ЮТест.ОжидаетЧто(...)` с учётом вариантов, заданных `СПараметрами` |

Метод с `СПараметрами` выполняется по одному разу на каждый набор параметров, поэтому проверок больше,
чем методов. В JUnit XML `tests` — это число проверок (51), в сводке Allure — 31: одноимённые проверки
параметризованного метода сводятся к одному тесту. Карточек в отчёте Allure — 51, по одной на проверку.

**Решение.** Сверять нужно одно с другим: число наборов из спецификации, число методов — по исходнику
тестового модуля (процедуры с `Экспорт`), число проверок — по отчёту прогона. Если после правки модуля
число проверок не изменилось, значит новая проверка не зарегистрирована в наборе.

**Как проверили.** На наборе из 31 метода: прогон 51 / 51 PASSED, JUnit XML — 51 запись, файлов карточек
Allure — 51, сводка Allure — 31. При проверке честности инверсия ожиданий даёт 51 красную проверку
(0 зелёных), то есть «краснеют» ровно все проверки.
