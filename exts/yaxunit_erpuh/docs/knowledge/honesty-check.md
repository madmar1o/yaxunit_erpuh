# Как проверяется, что тест умеет падать

**Симптом.** Набор тестов зелёный, но нет уверенности, что проверки действительно что-то проверяют:
тест может не вызывать тестируемый метод, не иметь утверждений или иметь утверждение, которое
истинно при любом результате.

**Причина.** Зелёный прогон сам по себе ничего не доказывает. Доказывает другое: если ожидания
в тесте заменить на противоположные, набор обязан покраснеть целиком. Тест, который не умеет
падать, — не тест.

**Решение.** Два шага перед каждым слиянием в `develop`.

**Шаг 1. Статический аудит** тестового модуля:

- каждый тест вызывает метод тестируемого модуля — 31 из 31;
- каждый тест содержит утверждения — 31 из 31, всего 48 цепочек `ЮТест.ОжидаетЧто`;
- имя теста начинается с имени проверяемого метода — 31 из 31;
- «пустых» тестов (без утверждений или без вызова метода) нет.

**Шаг 2. Мутационная проверка — инверсия ожиданий** в тестовом модуле:

| Было | Стало |
| --- | --- |
| `.Равно(…)` | `.НеРавно(…)` |
| `.ЭтоИстина()` | `.ЭтоЛожь()` |
| `.ИмеетТип("X")` | `.ИмеетТип("X!")` |
| `.ИмеетДлину(N)` | `.ИмеетДлину(N + 1)` |
| `.Заполнено()` | `.ИмеетДлину(0)` |

Нужен именно весь набор замен: если инвертировать только часть, тесты с вычисляемым результатом
могут остаться зелёными. Прогон инвертированного модуля обязан дать 0 зелёных проверок, после чего
модуль восстанавливается (контрольная сумма файла до и после — совпадает) и прогон повторяется
зелёным.

**Как проверили.** Прогон 16.10.2026:

| Шаг | Результат |
| --- | --- |
| Инверсия ожиданий | 69 замен: `Равно/НеРавно` 28, `ЭтоИстина/ЭтоЛожь` 19, `ИмеетТип` 13, `ИмеетДлину` 5, `Заполнено` 4 |
| Прогон инвертированного модуля | 51 проверка красная из 51 (31 failed + 20 errors), зелёных 0 |
| Восстановление | SHA256 совпал с версией в репозитории |
| Контрольный прогон | 51 / 51 PASSED |

Часть проверок падает «ошибкой», а не «падением»: инвертированное имя типа (`Тип("ОписаниеТипов!")`)
не существует, и проверка завершается исключением. Для честности теста это то же убийство мутанта.

**Ограничение.** Тестируемый код — общий модуль конфигурации на поддержке, прямая мутация продакшн-кода
в него не вносится. Инверсия ожиданий доказывает, что проверки исполняются и зависят от фактических
значений; на методах с вычисляемым результатом честность дополнительно подтверждается подменой факта
(например, моками).
